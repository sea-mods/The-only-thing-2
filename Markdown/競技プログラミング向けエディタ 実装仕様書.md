# 競技プログラミング向けエディタ 実装仕様書

## 0. 文書の目的

本仕様書は、競技プログラミング専用デスクトップエディタをAI Coding Agentが実装するための仕様書である。

単なるテキストエディタではなく、

> **Code → Compile → Test → Diagnose → Modify → Submit**

という競技プログラミング特有の反復作業を高速化することを目的とする。

特に以下を重要機能とする。

- C++コード編集
- 高速なコンパイル・実行
- Sample / Custom Test管理
- 出力Diff
- 実行履歴
- コードスナップショット
- Scratchpad
- 競プロ用Snippet
- 独立したLibrary Manager
- `#include <cp/...>` によるライブラリ利用
- 提出時のライブラリ自動展開
- Stress Test
- 将来的なヒューリスティックコンテスト支援

---

# 1. 基本思想

## 1.1 最重要目標

このアプリケーションは「多機能なIDE」を目指さない。

優先するのは、

> **競技中に思考を中断する操作を減らすこと**

である。

そのため、一般的なIDEに存在する機能でも競プロに不要なものは積極的に省く。

---

## 1.2 設計原則

以下を守ること。

### 原則1：操作数を減らす

頻繁な操作はショートカット1回で完結させる。

例：

```text
Ctrl + Enter
```

で、

```text
Save
↓
Compile
↓
Run selected tests
↓
Compare output
↓
Show result
↓
Save run history
```

まで行う。

---

### 原則2：通常のC++から大きく逸脱しない

独自言語や、

```text
use dsu
use dijkstra
```

のような独自構文は原則導入しない。

ライブラリは、

```cpp
#include <cp/dsu.hpp>
#include <cp/graph/dijkstra.hpp>
```

のように利用する。

---

### 原則3：開発時はモジュール化、提出時は単一ファイル化

開発時：

```cpp
#include <cp/dsu.hpp>
```

提出時：

```cpp
struct DSU {
    ...
};
```

へ自動展開する。

---

### 原則4：ユーザーのコードを勝手に変更しない

Lint、Suggestion、Library Recommendationなどは、

- 警告
- 候補表示

までとし、明示的操作なしにソースを書き換えない。

# 8. Workspace

1問題を1Workspaceとして扱う。

例：

```text

└─ .cpeditor/

   │  ├─ sample_02.in
```

# 24. Snippet

SnippetはLibraryとは別概念とする。

```text

```

をEditorカーソル位置へ挿入する。

### 24.1 Library Inline Insertion (Snippet連携)

Libraryとして登録されたコードは、`#include` による隠蔽だけでなく、必要に応じてEditor上に直接展開（スニペットとしての呼び出し）できる仕組みを提供する。問題に合わせて内部実装を少し書き換えたいケースに対応する。

- **Autocomplete連携:** Editor上で特定のプレフィックス（例: `@dsu` やエイリアス名）を入力した際、サジェスト候補にライブラリを表示し、選択時にソースコードをカーソル位置へインライン展開する。
    
      
    
- **依存関係の扱い:** スニペットとして展開された場合、そのライブラリが依存している他ライブラリ（Dependencies）は再帰展開せず、`#include <cp/...>` としてエディタの先頭（またはInclude領域）に自動追記するルールとする。

# 35. Submission展開処理

入力：

```cpp

#include <cp/b.hpp>

}
```

```text

└── C

B
└── C
```

```cpp

...

// ===== A =====

...

// ===== B =====

...

}
```

Cは1度だけ展開する。

---

# 36. Library Resolution Algorithm

以下の順序で処理する。

```text
1. main.cpp解析

2. #include <cp/...> を抽出

3. 対応Libraryを検索

4. dependenciesを再帰探索

5. cycle detection

6. topological sort

7. duplicate removal

8. system includes集約

9. library sourceをinline

10. submission.cpp生成
```

---

# 54. Error Handling

アプリケーションは以下によってCrashしてはいけない。

```text
Compiler not found
Source file missing
Invalid Library metadata
Library dependency cycle
Timeout
Program crash
Permission denied
Invalid UTF-8
Path contains spaces
Japanese file path
```

必ずUI上へErrorを表示する。


- **巨大出力への防御（UIクラッシュ対策）:** 無限ループや巨大出力でフロントエンド（Monaco Editor / React）がフリーズ・クラッシュするのを防ぐため、Backend側で `stdout` / `stderr` はそれぞれ一定サイズ（例: 1MB または 10万文字）でTruncate（切り詰め）し、末尾に `...[Truncated]` を付与してフロントエンドへ渡すこと。

# 72. Coding Agentへの指示

大規模な変更を行う前に既存Testを実行する。
