### 24. Snippet （追記）

**24.1 Library Inline Insertion (Snippet連携)**

Libraryとして登録されたコードは、`#include` による隠蔽だけでなく、必要に応じてEditor上に直接展開（スニペットとしての呼び出し）できる仕組みを提供する。問題に合わせて内部実装を少し書き換えたいケースに対応する。

  

- **Autocomplete連携:** Editor上で特定のプレフィックス（例: `@dsu` やエイリアス名）を入力した際、サジェスト候補にライブラリを表示し、選択時にソースコードをカーソル位置へインライン展開する。
    
      
    
- **依存関係の扱い:** スニペットとして展開された場合、そのライブラリが依存している他ライブラリ（Dependencies）は再帰展開せず、`#include <cp/...>` としてエディタの先頭（またはInclude領域）に自動追記するルールとする。

### 35. Submission展開処理 （ルールの追記）

AI実装時のコンパイルエラーを防ぐため、以下のルールを適用する。

  

- **インクルードガード:** 元のヘッダファイルに含まれる `#pragma once` や `#ifndef` などのインクルードガード行は、展開処理時に削除する（または展開コード内で無害化する）。
    
      
    
- **名前空間・マクロの衝突:** 複数ライブラリの結合による同名の構造体やマクロの衝突回避はユーザーの責任（各ライブラリ内で `namespace` を適切に切る等の運用）とする。
    
      
    

### 54. Error Handling （追記）

- **巨大出力への防御（UIクラッシュ対策）:** 無限ループや巨大出力でフロントエンド（Monaco Editor / React）がフリーズ・クラッシュするのを防ぐため、Backend側で `stdout` / `stderr` はそれぞれ一定サイズ（例: 1MB または 10万文字）でTruncate（切り詰め）し、末尾に `...[Truncated]` を付与してフロントエンドへ渡すこと。
    
      
    

### 72. Coding Agentへの指示 （項目追加）

**11**

Windows環境において Timeout または Cancel でプロセスを終了させる際、標準ライブラリの `.kill()` では親プロセスしか終了せず、子プロセス（実行ファイル）が孤児として残りファイルのロックを引き起こす問題がある。必ずJob Object API等を利用し、プロセスツリー全体を確実にKillする設計をBackendに行うこと。
